## Status and evidence rules

- **COMPLETE** requires the entire entry and its acceptance evidence; **PARTIAL** retains remaining dependencies; **MISSING** has no established functional implementation; **BLOCKED** records an explicit unresolved approval/decision. Code-coverage labels remain separate in the JSON and are not release acceptance.
- No module or entry is COMPLETE. All final acceptance remains OPEN. Candidate files, passing unit tests, schemas and synthetic Python supervision do not establish whole-product/live readiness.
- Existing verification fields and Module 01 evidence are preserved. New B03.5 evidence supports only its affected rows. No repeated Module 01 review or arbitrary Module 02 advancement.
- Local zero-paid inference and retained Node OCR remain development directions; formal hosted/Python amendments and clinical/privacy/operations appointments remain pending.
