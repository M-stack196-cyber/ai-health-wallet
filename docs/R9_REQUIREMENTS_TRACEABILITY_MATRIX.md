# R9 requirements traceability matrix

Generated by `python3 infrastructure/r9/build_traceability.py` from SRS v4.0 (`docs/AI_Health_Wallet_Revised_SRS_v4_0.docx`) and `docs/PRD_V2_MODULE_DELIVERY_TRACKER.md`. Do not edit by hand; change the tracker or the script and run it again. `backend/src/r9/traceability.test.ts` checks this file against the tracker.

## How to read this

- **Roll-up** is the worst status of the PRD rows that cite the requirement (order: BLOCKED, MISSING, NEEDS_REVERIFICATION, PARTIAL, IMPLEMENTED). A roll-up of IMPLEMENTED means backend/process scope with local synthetic evidence, as the tracker defines it. It is never release acceptance.
- **Direct** rows cite the requirement in their own Source mapping. **Inherited** means no row cites it, but the module's inherited-context line does (the tracker's own rule). Nothing is left without one of the two.
- **V verdicts**: VERIFIED_LOCAL = the cited synthetic tests exist and passed on the local disposable stack. PARTIAL = part of the expected result is proven and the rest is named. BLOCKED = the expected result needs an approval or resource that does not exist. None of these means accepted for release.
